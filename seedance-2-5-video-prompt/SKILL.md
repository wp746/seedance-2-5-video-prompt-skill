# Seedance 2.5 Video Prompt Director

## Goal

把创意翻译成模型可执行的导演指令。先选对 Seedance 2.5 工作模式，再控制参考职责、人物与空间连续性、时间戳、表演、动作物理、镜头、声音、转场和返修路径。

默认交付能直接复制的提示词，不把输出写成模型介绍、形容词堆砌或后台推理报告。

## Required references

每次使用先完整读取：

1. `references/model-capabilities-and-routing.md`：2.5 参数、甜点区、模式路由、2.0 迁移边界。
2. `references/prompt-architectures.md`：各模式的提示词公式与可复制骨架。
3. `references/quality-control-and-repair.md`：交付前检查、验收和最小返修路径。

以下情况再读取：

- 剧本、分镜、多镜头、30–180 秒、复杂动作、对白、广告或叙事项目：读取 `references/cinematic-production-playbook.md`。
- 用户要求用 Image2/GPT Image 生成资产板或分镜控制图：可借用现有 `image2-seedance-control` 的板式设计方法，但本 Skill 的 2.5 时长、素材数量、模式与提示词规则优先；不得继承其中 Seedance 2.0 的 15 秒硬限制。

## Authority and compatibility

- 把本 Skill 视为 Seedance 2.5 模型路由与参数的权威层。
- 继承 2.0 时期已验证的制作纪律：参考职责分离、连续性圣经、镜头计划先行、首尾状态交接、物理反馈、声音与表演、最小返修。
- 不继承已过时的 2.0 硬限制：每段必须 ≤15 秒、最多 9 张图、参考音视频总长 15 秒、不能纯音频驱动。
- 平台上限不等于稳定上限。总是同时遵守官方上限与创作甜点区；复杂度高时主动少传素材、缩短区间或拆分任务。
- 若即梦界面或用户提供的更新文档与本 Skill 冲突，以更新后的官方界面/文档为准，并指出发生变化的字段。

## Route the task first

先归入一个主模式；需要时组合后续修复模式：

| Intent | Primary mode |
|---|---|
| 从文本、图、视频、音频生成 4–30 秒 | `STANDARD_GENERATE` / 全能参考、首帧或首尾帧 |
| 一次生成 30–180 秒 | `ULTRA_LONG` / 超长视频 |
| 在已有 ≤30 秒成片前后续写 4–30 秒，最终不超过 60 秒 | `EXTEND` / 视频延长 |
| 修改已生成视频 | `SMART_EDIT` / 智能编辑或高级编辑 |
| 修改本地上传视频 | `VIDEO_EDIT` / 视频编辑 |
| 保留两段原片并补出中间过渡 | `SEAMLESS_TRANSITION` |
| 以粗/细颗粒 3D 白模控制走位、运镜或渲染 | `WHITE_MODEL` |
| 用简单多宫格故事板控制多镜头 | `MULTI_PANEL_STORYBOARD` |
| 合成或替换绿幕背景 | `GREENSCREEN` |
| 仅靠音频驱动画面 | `AUDIO_ONLY` |

不要默认选最长模式。按以下优先级判断：

1. 需要秒级、对白、动作或多人物精确控制：优先 4–30 秒常规生成。
2. 需要逐段验收后再决定剧情：优先延长或独立分段生成。
3. 内容节奏平缓、因果清晰、连续长镜头/纪录/Vlog/环境叙事：可用超长视频。
4. 复杂群像、密集对白、频繁换景或高难动作即使能做 180 秒，也优先拆成质量门控段。

## Workflow

### 1. Audit the brief

提取并锁定：

- 成片用途、平台、画幅、时长、语言、是否要字幕/BGM。
- 故事目标、核心冲突、情绪曲线、开头钩子、结尾落点。
- 角色、场景、道具、服装/妆造、时间天气、声音和特效。
- 已有素材、每项素材能控制什么、不可污染什么。
- 用户原始对白、旁白、品牌词和必须准确出现的文本。

若信息不足，只补影响生产的一两个变量。能安全推断时直接给出导演建议并继续。

### 2. Choose duration and complexity

先问“这一段只有一个核心戏剧任务吗”。一个时间段只承载一个主动作或一个情绪转折，辅以必要反应。

- 4–10 秒：单动作、单展示、单转场、短口播、局部修改。
- 10–20 秒：一个完整 beat，允许少量镜头变化。
- 20–30 秒：需要全局锁 + 明确时间戳分镜；不要靠散文自由发挥。
- 30–180 秒：先做段落/幕结构，再在段内写时间戳；减少每段状态变化和高风险动作。
- 复杂动作、长对白、多人交叠或精确物理交互：宁可拆段，不要用更长时长掩盖超载。

### 3. Build a reference-duty map

按实际上传顺序使用平台可见引用名：`@图片1`、`@视频1`、`@音频1`。每个参考只赋予清晰职责：

```text
@图片1：角色 A 的脸、发型、体型、服装；不控制场景和动作。
@图片2：场景空间、固定物、主光方向；不生成新人物身份。
@视频1：只参考 12–18 秒的运镜和动作节奏；不复制人物、背景或原片风格。
@音频1：只参考角色 A 的音色、语速和气息；台词以提示词原文为准。
```

遵守：

- 用户素材是最高优先级视觉事实，不重新设计。
- 参考职责不明确时，先写“读什么 / 忽略什么”。
- 多人物逐人绑定脸、服装、道具、站位、关系和声音，禁止用“所有人物参考这些图”一笔带过。
- 素材多于甜点区时，删去无关参考或按镜头分批上传；不要为了用满上限污染生成。

### 4. Lock continuity

内部建立简洁连续性圣经：

- `CHARACTER_LOCK`：身份锚点、体型、妆发、服装状态、声音、表演边界。
- `SCENE_LOCK`：空间轴线、入口出口、前中后景、固定物、光源与天气。
- `PROP_LOCK`：形态、材质、比例、初始/结束位置、持握方式、状态变化。
- `STYLE_LOCK`：媒介、写实度、色彩、对比、镜头质感、颗粒与禁用风格。
- `SCREEN_DIRECTION_LOCK`：人物左右关系、视线、运动方向、180 度轴。
- `AUDIO_LOCK`：对白原文、语言、音色、环境声、BGM/静音策略。

真人无参考图时，按 `年龄/种族 + 皮肤质感 + 3–4 个面部骨相细节 + 眼神底层情绪 + 发型状态 + 服装材质/新旧 + 体型/气质` 写角色，不只写“漂亮”“电影脸”。保留毛孔、细纹、雀斑、胡茬、衣料褶皱和轻微不对称等真实信息。

### 5. Make the shot plan before the final prompt

对每个镜头或时间段决定：

`时间范围 → 戏剧功能 → 景别/焦段 → 机位/轴线 → 主体动作链 → 非主体反应 → 环境/道具反馈 → 对白/声音 → 转场 → 结束状态`

时间戳必须覆盖全片、递增、不重叠、不留意外空洞。用户给帧号时先确认帧率；未说明时用秒级区间，除非项目确实需要逐帧卡点。

动作写成因果链：准备/蓄力 → 发起 → 接触 → 受力/惯性 → 环境响应 → 恢复/落点。避免同一时间要求主体完成互相冲突的动作。

### 6. Compile with the correct architecture

从 `references/prompt-architectures.md` 选择对应骨架。常规生成的默认顺序是：

```text
输出参数与任务目标
→ 参考素材职责
→ 一句话概述
→ 全局世界/连续性/风格锁
→ 时间戳镜头与表演
→ 声音与对白
→ 结尾状态/下一段接口
→ 全局禁止项与保持不变项
```

优先写可见、可听、可验证的指令。把“电影感”“高级”“真实”翻译成焦段、机位、光源、表面材质、惯性、呼吸、衣料、环境声、构图和节奏。

### 7. Preserve dialogue and sound

- 用户给出的对白、旁白、数字、品牌名和标点是锁定资产，不润色、不删减、不改写。
- 在台词前写人物心理、意图、呼吸、音量、音高、语速、停顿和听者反应，再给原文。
- 音色参考使用清晰、低噪的人声；写明 `@音频N` 控制哪位角色。
- 多语种直接用目标语言写台词并标注语言、口音/方言程度和口型同步。
- 需要后期自由度时明确：`纯净视频、无字幕、无背景音乐；保留指定对白与环境声`。完全静音时写 `无人声、无环境声、无 BGM`。

### 8. Deliver operator-ready output

默认使用用户工作语言。除非用户要求，不强制中英双语。

```markdown
# Seedance 2.5 生产提示词

## 导演判断
- 模式 / 时长 / 画幅 / 分辨率
- 为什么选这个模式
- 最高风险点

## 参考素材上传顺序
- @图片1 = ...
- @视频1 = ...
- @音频1 = ...

## 可直接复制 Prompt
```text
[完整自包含提示词]
```

## 验收与最小返修
- 只列需要用户实际检查的 3–6 项
```

用户只要 prompt 时，仅输出上传顺序和可复制 prompt。批量项目则按 `项目/集/场/段/镜头/版本` 命名，每个生成段独立自包含。

## Production rules

- 镜头运动必须有叙事动机；禁止无目的环绕、漂浮和全程自动推拉。
- 写清起始构图和结束构图，尤其是一镜到底、延长和无缝转场。
- 让非说话角色持续呼吸、眨眼、移焦、微表情和重心变化，避免木偶静止。
- 多人场景写清人数、站位、间距、动作先后、遮挡与各自身份；背景群演要有差异。
- 精确屏幕文字仍是高风险任务。剧情关键文字使用独立大字画面或后期排版；不要把长文本埋进复杂镜头。
- 不要用 `8K/HDR/史诗/电影感` 代替真实控制信息。
- 负向约束放在正向目标和保持不变项之后；只写与已知失败模式相关的负向项。
- 不为追求“完整”塞满参考素材和镜头数量。清楚的单一职责胜过素材堆叠。

## Final check

交付前按 `references/quality-control-and-repair.md` 检查：

1. 模式、时长、输入数量是否符合 2.5，而不是旧 2.0 限制。
2. 每个参考是否有唯一职责和忽略项。
3. 时间轴、镜头板和提示词是否同构。
4. 人物、场景、道具、方向、声音是否锁定。
5. 对白是否逐字保留，时长是否容纳表演和反应。
6. 是否为最可能的失败准备了最小返修方式。
